1 · The zip

Deployment_2026_11_03_bb3e80f1a.zip: 495 changed or added files (248 backend, 205 frontend, 38 Helm chart, 3 Dockerfiles, 1 Spark job) and 13 files to delete, all in the retired worker chart (listed in DELETED.txt). 2 · Deployment steps, in this order

The charts changed this time. The scheduler no longer runs feeds. A new job-worker chart replaces your executor Deployment, the old worker chart is removed, and a query-pods chart is added (it installs nothing until sizes are set). Follow the steps in order and nothing is left without an owner.

2.1 · Before you start (5 minutes)

  1. Take a database backup (a PostgreSQL snapshot). This update changes how a paused schedule is stored. The change is safe going forward, but a backup makes a rollback exact.
  2. Save your own copy of k8s/querystudioapi-helm/env/uat.yaml if you edited it in UAT. The zip carries a new uat.yaml; put your own lines back after copying (2.2). Your uat.site.yaml is not in the zip and is kept.
  3. Note the name of your executor Deployment and Service (the one you applied from your own manifest): 
    kubectl get deploy,svc -n 45646 | grep -i -E "executor|worker"

2.2 · Copy the code

  1. Unzip Deployment_2026_11_03_bb3e80f1a.zip over the source tree of your UAT deployment (same paths).
  2. Delete the 13 paths in DELETED.txt. They are the whole k8s/querystudioapi-helm/worker/ folder: 
    rm -rf k8s/querystudioapi-helm/worker
  3. If you saved your own uat.yaml lines, put them back now. The new file differs from the old one in these places only:
    • config.workerPool is gone (the multi-pod worker pool is retired);
    • config.reportsPod.enabled: true and config.downloadsPod.enabled: true: the screen sends report work to the reports pod and Download Centre work to the downloads pod (from the 10-30 update);
    • querystudio.scheduler.worker_host: querystudio-scheduler and querystudio.executor.worker_host: querystudio-job-worker: where the API pod asks the scheduler and the job-worker about their background jobs.

2.4 · Install the charts

From k8s/querystudioapi-helm/:

./deploy.sh uat

Run the whole script, not one chart. It installs in this order, which is the safe order: qs-api → qs-feed-worker → qs-job-worker (new) → qs-scheduler → qs-query-pods (new, empty until sizes are set) → qs-published-api → qs-reports → qs-downloads → qs-ui. Each step waits until its pods are Ready (up to 10 minutes).

  • Feed-worker before the scheduler. From its first start the new scheduler hands every feed run to a feed-worker pod. If no feed-worker pod is running, runs wait as pending (Component Health says so). uat.yaml has feedWorker.enabled: true; keep at least one replica.
  • Job-worker runs every background job that is not a feed: scheduled reports and subscription e-mails, data-quality rules, pipelines, DataFlow, custom jobs, dropdown lists, mirrors. It is the same program as your executor under its new name, port 8002, 2 replicas. The old executor can stay up during the switch: both take jobs safely and only one runs the timed jobs.
  • Scheduler gains a start-up probe (up to 10 minutes for a slow first start) and the permission to resize query pods (rbac-query-pods.yaml, limited by name to query-pod Deployments).

2.5 · Remove what is retired

  1. When kubectl get pods -n 45646 | grep job-worker shows the job-worker pods Running / Ready, delete your old executor Deployment and Service (the names from 2.1): 
    kubectl delete deploy <your-executor-deployment> -n 45646
kubectl delete svc <your-executor-service> -n 45646
  2. Remove the old worker chart and its secret: 
    helm uninstall qs-worker -n 45646
kubectl delete secret qs-worker-auth -n 45646 --ignore-not-found
  3. helm list -n 45646 now shows qs-api, qs-feed-worker, qs-job-worker, qs-scheduler, qs-query-pods, qs-published-api, qs-reports, qs-downloads, qs-ui, and no qs-worker.

2.6 · What happens by itself on the first start

  • New tables and columns are added (reports, value lists, entitlement, query pods, version pins, switched-off records).
  • Schedules: "paused" gets its own column (schedules.enabled). Every schedule that was paused stays paused. This runs once.
  • Delete means switch off: every settings table has an "active" flag, on by default. From now on, deleting a dataset, report, feed, value list and so on switches it off, and it can be switched on again from Switched Off (admin).
  • Who may use which screen is now a list of permissions per role. On day one it gives each role exactly what it had before (proven on 1,443 routes × 7 roles: 0 differences). Nothing to set up.

2.7 · If you must roll back

  1. helm rollback each release to its previous revision (helm history qs-scheduler -n 45646 shows it), and helm uninstall qs-job-worker qs-query-pods -n 45646. Re-apply your executor manifest and re-install the worker chart from the old tree.
  2. Deploy the previous images.
  3. Restore the database backup from 2.1. Without it the old code still starts, but it shows switched-off rows as live and reads a paused schedule as running.

3 · Check after deploying (10 minutes)

  1. Component Health is green. The feed queue consumer reads healthy (a feed-worker pod is taking runs).
  2. The scheduler log at start says this process is the scheduler and Feed queue worker NOT registered in this process.
  3. Press Run now on a feed. The message says "Feed run queued for a feed-worker pod", the run completes, and the file arrives. The feed-worker log shows the run; the scheduler log does not.
  4. A scheduled report or a subscription e-mail sends (it now runs on the job-worker).
  5. The two pods answer: https://querystudio-reports-45646.np5-gl.apaas4.claude.intranet/health and https://querystudio-downloads-45646.np5-gl.apaas4.claude.intranet/health each show {"status": ...}. If an address does not open, set reportsPod.enabled: false / downloadsPod.enabled: false under config: in uat.yaml and run ./deploy.sh uat again. Reports then go to the main pod as before.
  6. Open Reports → New report → From a template: 15 templates are listed, including P&L bridge, Statement, Limit usage, Ageing and Break report.
  7. Open any report, then More → View in another theme: the report redraws, and the Excel / PDF download follows the theme you picked.
  8. Download an Excel: the file name is the report's name and the date, not a long code.
  9. Press Ctrl+Shift+R once in the browser if a screen still looks like before.

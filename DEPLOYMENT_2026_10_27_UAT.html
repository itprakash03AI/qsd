1 · Before you start: what only your UAT can supply

The UAT values file k8s/querystudioapi-helm/env/uat.yaml holds everything QueryStudio already knows about UAT: its namespace, registry, hostnames, row security and Spark Connect. Nine values can only come from you. They are marked __SET_PER_ENV__, and the charts refuse to render while any marker is left, so nothing can start half-configured.

  1. Copy env/example.site.yaml to env/uat.site.yaml. That file is ignored by git, so never commit it.
  2. Fill in UAT's own directory. Use the UAT groups, never the PROD ones: 
    querystudio:
  auth:
    type: ad                      # or: local
    ad_server: "ldaps://<UAT AD server>:636"
    ad_domain: "<DOMAIN>"
    ad_base_dn: "DC=...,DC=..."
    ad_service_account: "<service account>"
    ad_admin_groups:   "CN=<UAT admins group>,OU=...,DC=..."
    ad_analyst_groups: "CN=<UAT analysts group>,OU=...,DC=..."
    ad_viewer_groups:  "CN=<UAT viewers group>,OU=...,DC=..."
  3. The master key. Read it once from Vault and give the same value to all five deployments (api, scheduler, executor, reports, published-api) as QUERY_STUDIO_SECRET_KEY.
    • For an existing UAT, it must be the key that UAT has always used. A different key cannot read the saved connection passwords.
    • For a new UAT, create one key and keep it in Vault.
    oc create secret generic qs-master-key --from-literal=QUERY_STUDIO_SECRET_KEY="$KEY_FROM_VAULT"
for d in <api> <scheduler> <executor> <reports> <published-api>; do
  oc set env deploy/$d --from=secret/qs-master-key
done
  4. The environment name is already uat in both places in uat.yaml; leave it as it is. If it were blank, the feed SLA watcher would stop and say so, because a UAT alert must never reach Netcool labelled PROD.
  5. Only if UAT users will run feeds on Spark pods (Spark Connect is already set): add to uat.site.yaml 
    querystudio:
  spark_k8s:
    enabled: true
    callback_base_url: "http://querystudio-api.<UAT app namespace>.svc:8000"
  feed_generation:
    webhook_secret: "<a random secret>"
    Without these, feeds run on the built-in engine (Native). That works for every feed; it is just slower for very large ones (see §4).

2 · Install or upgrade

A new UAT

  1. Unzip Deployment_2026_10_27_d6266c91a_FULL.zip.
  2. Build the images:
    • backend/ → the API image, also used by the scheduler, executor, reports and published API;
    • frontend/ → the UI image;
    • spark/ → the Spark job image, only if you use Spark pods.
  3. Create the empty PostgreSQL database named in uat.yaml (querystudio on postgresqlnew). QueryStudio creates every table itself on first start. There is no SQL script to run.
  4. cd k8s/querystudioapi-helm && ./deploy.sh uat. It applies env/uat.yaml, then your env/uat.site.yaml, to every chart.

An existing UAT on 9572643d8

  1. Unzip Deployment_2026_10_27_d6266c91a.zip over the source tree you built 9572643d8 from.
  2. Delete the paths listed in DELETED.txt.
  3. Rebuild the images for the folders listed in MANIFEST.txt, then run ./deploy.sh uat.
  4. Database: this release adds 8 tables and about 116 columns. They are added on the first start; no existing column changes type. The tables are: value lists (2), data entitlement (4), Netcool rules, and the SQL each feed run sent.

3 · Check it is up (10 minutes, before users arrive)

  1. Configuration: python scripts/verify_prod_config.py --profile uat --base-url https://<UAT API> --site-file k8s/querystudioapi-helm/env/uat.site.yaml. It only reads. It says whether each pod loaded the file this release expects.
  2. Pod logs: none says WAITING for the key, MASTER KEY MISMATCH or __SET_PER_ENV__.
  3. Sign in as a member of each AD group:
    • an admin sees Admin;
    • an analyst can build reports;
    • a viewer can only open them.
  4. Admin → Monitoring → Component Health: every pod and every connection is green. A connection's Test button succeeds.
  5. One feed: Run Now on a small feed. It delivers, and its run shows each step with a time.

4 · What is new for UAT users (since 9572643d8)

AreaWhat users will see
Feeds list
  • Grouped by feed group, template, schedule or any template value. For example, every FX-AMER feed sits under one heading, with Open all / Close all.
  • The Schedule column says the schedule in words ("Month end", "Every working day"). It used to say "Off".
  • Switched-off feeds are hidden until you ask for them.
Feed form
  • It opens in the same window as the Download Center's preview. You can move it by its title bar, resize it from the corner, maximize it, and minimize it to its title. It closes only with its Close button, so a stray click or Escape never loses your work. The steps are listed down the left side.
  • "Extra filters (optional)" replaces "WHERE Clauses".
  • The Review step says which engine will run the feed (Native or Spark) and why.
  • A path that starts or ends with a space is refused, with the reason.
Which engine runs a feed
  • A big or wide run goes to Spark by itself. The row count is checked on the source first, and 600 columns count as six times the rows of 100. Anything else runs on Native.
  • An engine that UAT has not switched on is not offered. Airflow, for example, no longer appears where it cannot run.
Cancelling a feedCancel now also stops the query at the source: Starburst/Trino, Snowflake, Oracle, Databricks and DuckDB. It also stops an upload that is in progress. The run then shows what was stopped: "Stopped at the source: Trino / Starburst query <id>".
A run that keeps failingIf the pod running a feed is killed (for example, out of memory), the run is tried once more. If that is killed too, the run fails, and the message says why and what to change. It used to restart again and again.
MemoryA pod takes only as many feed runs as its memory can hold. Wide runs are weighed by their width. A wide run used to be able to take the scheduler down.
AWS S3 through a VPC endpoint
  • Feeds read with the connection's credentials, as the query builder always did; they used to read with none.
  • An S3 error now starts with what S3 answered ("S3 answered HTTP 403 (AccessDenied) ...").
  • A region the connection does not use is no longer reported.
Reports
  • Canvas reports export to Excel (one sheet with real charts) and PDF, laid out as on the screen.
  • They also work on share links, embeds and dashboard tiles.
  • Parameter choices are smarter and come from the source table, another table or a saved value list.
  • There is no row limit by default.
Data entitlementWho can see which values can be set per group or user, by column. It is off until an admin turns it on. A report says when entitlement limits what it shows.
Published APIsAn API can combine data from two sources in one answer. Row security is applied last on every source.

Very wide feeds on Spark (fixed in this release)

A feed of about 600 columns, pinned to Spark and split by a partition column, used to run out of memory on small Spark pods. The memory each pod is given outside Java's heap was too small for that width, and the driver had too little room to send the file.

The cause was measured inside the pods, and the sizing rule now follows those measurements. The same 2-million-row, 600-column feed then delivered correctly on the test rig's small pods. The file was byte-for-byte the same as the one the built-in engine produced, and no pod ran out of memory.

With the default Spark pod sizes, which UAT uses unless you change them, nothing changes.

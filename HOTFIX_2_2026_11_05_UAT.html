UAT hotfix 2, 2026-11-05: AWS portal logins on every road

Release d8c734ddd, tag release/2026-11-05-d8c734ddd, on top of hotfix 1 (8f8d3272a). Zip: Deployment_2026_11_05_d8c734ddd.zip. Apply hotfix 1 first if you have not.

The full results are in AWS_PORTAL_EVERY_ROAD_2026_11_05.html.

Delivered before the CI and frontend suites finished, because of today's demo. The results will follow.

1 · What it fixes

  • Feeds with a System Account fail on the feed worker on hotfix 1. They now log in. Jobs on the job worker use the same fix.
  • Test and browse on Personal now work for a person who is logged in.
  • Reports on a plain parquet table now read its registered folder. Iceberg tables were not affected.
  • A published API says its connection could not log in, instead of "Internal server error".
  • Plain words replace the raw auth_mode='portal' requires... error.
  • A wrong Snowflake key passphrase always says the passphrase is wrong.

3 · Deploy

  1. Build querystudio-api, querystudio-reports and querystudio-published-api. The api image also runs the feed worker, job worker and scheduler.
  2. Run ./deploy.sh uat.
  3. Check: on a connection with your Vault account, run Test, browse, a SQL query, a report and one feed.

A connection on Personal with nothing saved will ask for the password once more after the restart. It cannot run reports on the reports pod, published APIs or feeds. For those, pick a System Account on the connection.

2 · What changes for users

AreaWhat users will see
Filter at the sourceA report on a dataset built from SQL now lists the fixed values in that SQL's WHERE clause (for example SYSTEM_ID IN ('SAPADB', 'MOTIFADJ') and BUSINESS_CLOSE_DATE = '2025-09-30') under Filter at the source. Tick one and it becomes a question when the report runs: the chosen value goes into the query and runs on the source. One value runs as =, several as IN (...). Left empty, the report runs exactly as the query is written (the viewer reads "As in the query: SAPADB, MOTIFADJ"). Filter the results still filters the rows that come back.
Date questionsA date can be any date on a calendar, not only the dates found in the data. In the report editor, "Days the viewer may pick" chooses Any date or Only dates that have data. New date questions start as Any date.
Column orderIn the report builder, "Column order" numbers each column and has ▲ / ▼ buttons (dragging still works).
Text columns that look like datesA column the source says is text is no longer treated as a date because its name contains "date", "ts" or "settlement" (for example "Trade Comments"). Existing datasets keep their stored types until their columns are detected again (Datasets → Auto-detect).
Connections pageUses the full width of the screen; the new / edit form opens wider and scrolls less.
Vault System AccountsAn account's username and password are one login. A connection that picks a System Account and has a typed username but no password now logs in as the account's user (before, it sent the typed name with the Vault password and Starburst answered HTTP 401). A connection with its own username and password still uses those. Kafka, the Oracle destination and the feed's Test button follow the same rule.
SFTP logins from a System AccountThe account has an Allowed hosts field. Its login is sent only to those SFTP servers; when an admin saves the account, QueryStudio reads each server's key and checks it on every login. A feed author who is not an admin can use the account only with those hosts; an admin can point a feed at a new host. SFTP destinations already saved and already sending the account's login keep working.
Report and download pods now usedThe reports pod and the downloads pod were installed by deploy.sh but the screen never called them: every report and every Download Centre request went to the main API pod. Now the screen sends report requests to https://querystudio-reports-45646.np5-gl.apaas4.claude.intranet and Download Centre requests to https://querystudio-downloads-45646.np5-gl.apaas4.claude.intranet; everything else still goes to the main API. Users see no difference except that report work no longer slows down queries on the main pod.
Deleting a datasetA dataset that reports are built on can no longer be deleted. The message names those reports; delete or move them first.
Popups look like the rest of the appEvery "are you sure?", message and "please enter" popup (about 120 of them: delete, rerun, stop a run, force-start and so on) used the browser's own grey box ("...says"). They now open the app's own window, with a clear button named for the action (Delete, Rerun, Run now), red when it deletes. What each one asks and does is the same.
Shared and embedded linksOffer only the values written in the query for a source question, and never show the query's SQL or table names.

3 · Check after deploying (5 minutes)

  1. Component Health is green.
  2. Open a report built on your JOIN dataset: Edit → Filters step shows Filter at the source with SYSTEM_ID and BUSINESS_CLOSE_DATE.
  3. Tick BUSINESS_CLOSE_DATE, save, open the report: the date is a calendar; run it for 2025-09-30 (the rows you had) and for a date with no data (no rows, no error).
  4. The Connections page fills the screen.
  5. A Starburst connection that uses a Vault System Account: Test connects.
  6. One SFTP feed that delivers with a System Account: run it once, the file arrives. Then open System Accounts, fill Allowed hosts with that server and save.
  7. Try to delete a dataset a report uses: the app's own window asks (not the browser's grey box); press Delete and it is refused, naming the report.
  8. If any popup still looks like the browser's grey box, the browser is holding the old screen: press Ctrl+Shift+R once.
  9. The two pods answer (do this first if a report or the Downloads page does not load): open https://querystudio-reports-45646.np5-gl.apaas4.claude.intranet/health and https://querystudio-downloads-45646.np5-gl.apaas4.claude.intranet/health in the browser; each must show {"status": ...} with no certificate warning. Then open a report, press Execute, and open Downloads: both work.

If a pod's address does not open (no DNS name or certificate for it yet in UAT), switch the screen back to the main API for that pod and nothing else changes: in k8s/querystudioapi-helm/env/uat.yaml set reportsPod: enabled: false (and / or downloadsPod: enabled: false) under config:, then run ./deploy.sh uat again. Reports and downloads then work exactly as before this update.

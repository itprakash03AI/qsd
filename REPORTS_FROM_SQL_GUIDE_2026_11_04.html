Setting up reports from SQL

For people who set up reports from QueryStudio's PostgreSQL database. Ready-to-run script: scripts/sql/reports_from_sql.sql.

You describe a report once, using names people already know, and make one SQL call. QueryStudio saves it through the same checks as the screen. You can then open, edit and share it on the screen like any other report.

1 · The two statements to remember

SELECT qs_report_apply($spec$ { ...your report... } $spec$::jsonb, true);   -- returns a request number

SELECT request_id, report_name, state, action, report_id, slug, error
FROM qs_report_apply_status ORDER BY request_id DESC LIMIT 25;              -- what happened
The second valueWhat it does
trueA dry run. Checks every name and saves nothing. The status says "would create" or "would update".
falseSaves the report. The status says "created" or "updated".

Your request is picked up within about a minute. Until then its state is pending. It then becomes done or failed, and error says why in plain words.

Keep the $spec$ marks. They let your text hold quotes without any escaping.

3 · Where the data comes from

The first four types read a dataset. Name one that exists:

"dataset": "FACT_TETB_REPORTS"

Or create one from a query. QueryStudio detects its columns, and later calls can reuse it by name:

"dataset_sql": {"name": "FACT_TETB_REPORTS", "connection": "aws-prod", "sql": "SELECT ..."}

Give every column a clear name with AS "My Name" in the query. Those are the names you use everywhere else. A date column must be a real date, not text, for the date slots of a design to accept it.

5 · A table

SELECT qs_report_apply($spec$ {
  "name": "Finance - balances by company",
  "type": "table",
  "dataset": "FACT_TETB_REPORTS",
  "columns": ["Sap Company Code", "Transactional Currency", "USD Currency Amount"],
  "order_by": [{"column": "USD Currency Amount", "direction": "desc"}],
  "published": true
} $spec$::jsonb, true);

6 · A pivot

SELECT qs_report_apply($spec$ {
  "name": "Finance - pivot",
  "type": "pivot",
  "dataset": "FACT_TETB_REPORTS",
  "pivot": {"rows": ["Sap Company Code"], "columns": ["Transactional Currency"],
            "values": [{"column": "USD Currency Amount", "aggregation": "sum"}]}
} $spec$::jsonb, true);

aggregation can be sum, avg, count, min, max or count_distinct. A pivot's rows and columns must be category columns, not dates.

7 · A canvas: your own page

SELECT qs_report_apply($spec$ {
  "name": "Finance - my page",
  "type": "canvas",
  "dataset": "FACT_TETB_REPORTS",
  "tiles": [
    {"kind": "number", "title": "USD in all",
     "measures": [{"column": "USD Currency Amount", "aggregation": "sum"}],
     "layout": {"x": 0, "y": 0, "w": 4, "h": 3}},
    {"kind": "hbar", "title": "Top 10 companies", "top_n": 10,
     "dimensions": ["Sap Company Code"],
     "measures": [{"column": "USD Currency Amount", "aggregation": "sum"}],
     "layout": {"x": 0, "y": 3, "w": 8, "h": 8}}
  ]
} $spec$::jsonb, true);

The page is 12 columns wide: x is where a tile starts across, w its width, y where it starts down, h its height.

A tile the screen would refuse is refused here too, with the same words. For the less common kinds, the easiest way to see the shape is to build one on the screen first.

8 · A ready-made design

SELECT qs_report_apply($spec$ {
  "name": "Finance - top N",
  "type": "template",
  "dataset": "FACT_TETB_REPORTS",
  "template": "top_n_ranking",
  "slots": {"category": ["Sap Company Code"], "amount": ["USD Currency Amount"]}
} $spec$::jsonb, true);

Slots marked "if any" can be left out. A date slot needs a date column, an amount slot a number column, a category slot a text column.

10 · A report on your own SQL

SELECT qs_report_apply($spec$ {
  "name": "Finance - my own query",
  "type": "sql",
  "connection": "aws-prod",
  "sql": "SELECT ... your query ..."
} $spec$::jsonb, true);

This saves your query as an SQL file named like the report. To use a file already saved, give "sql_file": "its name" and no sql.

This type needs a database connection (Trino, Starburst, Snowflake, Oracle and so on). For a connection to S3 files, use type table with dataset_sql: it takes the same query.

11 · When something is refused

error saysWhat to do
This dataset has no column called 'X'. It has: ...Copy the name from the list it gives. Capitals don't matter; spelling does.
There is no dataset named 'X'.Check the name, or run the dataset_sql call first and wait for it to finish.
2 reports are named 'X'.Two people own a report with that name. Rename one on the screen.
'X' is not a report type.Use one of the five in section 2.
'Date' needs a date column.Your query returns text for that column. Keep it a real date in the query.
Still pending after a few minutesTell your administrator: the scheduler picks these up, so it may not be running.

12 · For administrators

  • Who may run it: a request is applied with administrator rights, stamped with who asked. Grant EXECUTE on qs_report_apply to the release or DBA role only, as for qs_feed_template_apply.
  • Never insert into the report tables directly. That skips the checks and leaves no version history.
  • Where they appear: the function and view are created by the scheduler within a minute of the first start on the new version. The job is report_requests on the background jobs screen.
  • Deleting a report: on the screen. It is switched off and can be switched back on. A name held by a switched-off report can't be reused until then.

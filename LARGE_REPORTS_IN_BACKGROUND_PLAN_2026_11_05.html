Large reports: run in the background, tell the user when ready

Plan for your sign-off, 2026-11-05. Nothing here is built yet, and it is not in the bundle you are deploying.

What I need from you: yes or no on the five decisions in section 6. My recommendation is next to each one.

1 · The idea

Before a report starts, QueryStudio works out how big it could be. If it is large, the user is told straight away that it is running in the background and that they can leave. When it finishes they get a notification that opens the finished result, with no second run. From there they can filter, sort, drill and export as usual.

A large report runs the same way as any other report. Only what the screen says and who gets told changes. If the user stays on the page, the result appears there. So a wrong estimate costs one extra message, not a wrong answer.

4 · The rules

  1. Large means rows × columns. 5 million rows of 10 columns is light; 1 million rows of 500 columns is not. One setting, business_reports.background_above_cells, starting at 500 million cells (5M rows × 100 columns). Your query is 6.4 billion, so it qualifies.
  2. The number is "up to", never "will return". Iceberg's count is before the WHERE and before any grouping, so a summary report returns far fewer rows. Partition filters narrow it first. Deleted rows are still counted, so it stays an upper limit.
  3. Unknown stays unknown. Snowflake, Trino, Oracle and tables not in the cache have no count. The screen shows no number and never says 0. These reports get the background message after 60 seconds of running instead of 10 minutes.
  4. This never blocks a report. Large reports still run, and nothing is cut. If the count cannot be read, the report runs as it does today.
  5. Pressing Run twice joins the same run. Same user, report version, parameter values, row security and data version. Only an unfinished run is joined. Two different users always get separate runs, so one person's row security can never reach another.
  6. Only the person who ran it can open the link. The link is checked on the server against the user and the report's access at the time it is opened. Forwarding it gives someone else nothing.
  7. Email holds no data. Report name, parameters, row count and a link that needs a login. No file and no rows are attached. Parameter values are left out if decision 5 says so.
  8. Results expire by the existing retention. If a result has been cleaned up, the link says so and offers Run again. It never shows a blank page.
  9. Row security does not change. The run, the stored result and the download all use today's rules.

1 · How to apply a changes-only bundle

  1. Start from the source tree you built Deployment_2026_10_15_a8259913 from.
  2. Copy this bundle's files over it at the same paths. Skip MANIFEST.txt and DELETED.txt.
  3. Delete every path listed in DELETED.txt.
  4. Rebuild the images that the changed paths belong to:
    • API / scheduler: anything under backend/;
    • UI: anything under frontend/;
    • Spark job image: anything under spark/.
    MANIFEST.txt names the commit and every file. When in doubt, rebuild all of them; they share one commit.
  5. Roll out. Database changes apply themselves when the pods start (§4).

"QueryStudio was updated — this tab is running an older build", again and again The UI's build id was the build TIME. Every UI replica, and every rebuild of the same code, had a different id, so a tab whose requests landed on a different replica was told it was old. Fixed in this bundle (frontend/vite.config.ts).   • the UI shows the login page, with a notice that sign-in is not configured;
  • the API log says LOGIN REQUIRED but NOT CONFIGURED.
Guest mode exists only if someone deliberately sets auth.type=none. Proven on the release image: all 417 read routes refused an anonymous caller. 5 · Configuration without the Helm chart: environment variables

You do not need the chart's ConfigMaps. Every config key can be set as an environment variable: QUERYSTUDIO_<SECTION>_<KEY>, which overrides config.json. For a whole section, give its value as JSON. Keep these values in ONE ConfigMap (and one Secret for passwords), and attach both to every backend deployment:

oc create configmap qs-auth \
  --from-literal=QUERYSTUDIO_AUTH_TYPE=ad \
  --from-literal=QUERYSTUDIO_AUTH_AD_SERVER=ldaps://<your-dc>:636 \
  --from-literal=QUERYSTUDIO_AUTH_AD_DOMAIN=<DOMAIN> \
  --from-literal=QUERYSTUDIO_AUTH_AD_BASE_DN="DC=...,DC=..." \
  --from-literal=QUERYSTUDIO_AUTH_AD_ADMIN_GROUPS='["<admin group>"]' \
  --from-literal=QUERYSTUDIO_AUTH_AD_ANALYST_GROUPS='["<analyst group>"]' \
  --from-literal=QUERYSTUDIO_AUTH_AD_VIEWER_GROUPS='["<viewer group>"]' \
  --from-literal=QUERYSTUDIO_AUTH_AD_SERVICE_ACCOUNT=<svc account>
oc create secret generic qs-auth-secret --from-literal=QUERYSTUDIO_AUTH_AD_SERVICE_PASSWORD=<password>

for d in <api deployment> <scheduler deployment>; do
  oc set env deploy/$d --from=configmap/qs-auth
  oc set env deploy/$d --from=secret/qs-auth-secret
done

6 · Encryption: one key, the API owns it

  • Stored credentials are envelope-encrypted. The master key (QUERY_STUDIO_SECRET_KEY) wraps the data keys held in the new table encryption_data_keys.
  • Every component must get the SAME QUERY_STUDIO_SECRET_KEY (API, scheduler, workers), as in 2026-10-15 §2a. Only the API creates keys; the other components wait for them.
  • encryption_data_keys belongs to its ENVIRONMENT. A configuration release never carries it: PROD's keys are wrapped by PROD's master.
  • A credential save refused for want of a key now answers 503, with the fix in the message, on every route.

6b · The Spark job image: Jetty CVEs (CVE-2026-2332, CVE-2026-10050)

This bundle carries three Spark files.

  • spark/jobs/generic_feed.py: the job now pins an Iceberg snapshot in the way its Spark version accepts. Spark 4.2 refuses the old option, and Spark 3.5 silently ignores the new one, so the job chooses by version. Rebuild your Spark job image with this file even if you stay on Spark 3.5. Proven on 3.5: 41/41, 7/7, 10/10 on the pods.
  • spark/Dockerfile.spark42 and spark/scripts/strip_hadoop_jetty.py: the TESTED Spark 4.2 + Jetty 12.1.14 image, which clears both Jetty CVEs. It is opt-in: the default spark/Dockerfile is still Spark 3.5.3.

How to build it, and every test behind it, is in SPARK_IMAGE_JETTY_2026_10_19_v5.html (on qsd; §0 is the recipe). In short:

  1. build Spark 4.2.0 from source with -Djetty.version=12.1.14 -Phive -Phive-thriftserver;
  2. build the image with Dockerfile.spark42;
  3. in QueryStudio, set the Spark image to it and the driver memory to 2g.

Do not use an image with Jetty removed from spark-core. It passes the scan, and every Spark job fails at start-up.

Iceberg on Spark 4.2 uses Iceberg's nightly 1.13 build. Every test passed with it, including real AWS merge-on-read, but swap in the 1.13.0 release when it is published.

7b · Fixed 2026-10-22: a Spark run's file size

The defect: execution.file_size_bytes read 0 for every Spark run that QueryStudio itself delivered, meaning a local destination or a delivery chain. The job reports the size only when it delivers the file itself (SFTP, S3, local in the pod), and those runs were always correct.

The fix: core/feed_engine.py, deliver_completed_spark_run, now records the size of the files it actually sent. Proven on the Docker Spark pods: 139 bytes recorded, where it was 0.

Spark → Oracle stays 0 bytes: the job writes the table directly and no file exists.

9 · Rollback

You chose to deploy without a database backup. Know what that means for a rollback:

  • The new tables and columns are additive, and the old code ignores them.
  • api_access_log.view_id stays nullable, which is harmless to the old code.
  • Stored credentials are different. Once this release starts, it encrypts them with its data keys (encryption_data_keys). The 2026-10-15 code cannot read those.

To roll back, redeploy the Deployment_2026_10_15_a8259913 images, then re-enter each connection's password (Admin → Connections), because the old code cannot read the re-encrypted ones. Never drop encryption_data_keys while this release is running.

1 · First: the master key comes from your pipeline, for EVERY component

Why the scheduler and other components failed last time: only the API was given the master key. Connection passwords are stored encrypted, and every component that uses a connection must decrypt them with the same key:

  • the scheduler (feeds);
  • the executor;
  • reports;
  • the published API;
  • connection health checks.

The pods still start without the key, but any work that needs a password fails.

QueryStudio reads the key from the environment first (QUERY_STUDIO_SECRET_KEY), on every component. No code change is needed. Your pipeline only has to:

  1. read the master key once from Vault;
  2. inject it as QUERY_STUDIO_SECRET_KEY into all five deployments: api, scheduler, executor, reports, published-api.
# example: one Secret, attached to every deployment
oc create secret generic qs-master-key --from-literal=QUERY_STUDIO_SECRET_KEY="$KEY_FROM_VAULT"
for d in <api> <scheduler> <executor> <reports> <published-api>; do
  oc set env deploy/$d --from=secret/qs-master-key
done

It must be the key the API has been using. If the API ever created its own key file, use that value in Vault. A different key cannot read the passwords already saved.

Check after the restart:

  • no pod logs WAITING for the key or MASTER KEY MISMATCH;
  • Admin → Monitoring → Component Health shows the connections healthy;
  • a connection's Test button succeeds.

Reproduced on the rig on 2026-10-22: a scheduler with no key logs "WAITING for the key … Set QUERY_STUDIO_SECRET_KEY for every component", and one with a different key logs "MASTER KEY MISMATCH". Both keep running; only the work that needs a password fails.

3 · Apply

  1. Make sure §1 is done: the same QUERY_STUDIO_SECRET_KEY on all five deployments.
  2. Unzip over the source tree you built 0f0a02d5d from, then delete the paths in DELETED.txt.
  3. Rebuild the images for the folders that changed, as listed in MANIFEST.txt:
    • backend/ → the API image (also used by the scheduler, executor, reports and published API);
    • k8s/querystudioapi-helm/ → re-apply the published-api, reports and downloads charts;
    • frontend/ → the UI image;
    • spark/ → the Spark job image.
  4. Roll out. There are no database changes in this bundle.
